## 真实自动转录闭环

在新的隔离项目中注册仅用于验收的本地 runner，安装匹配 `source=phone.recorder` 的事件规则后，再上传合成录音。实际 `edc-runner tick` 自行发现事件并领取任务，调用本机 Qwen，生成“预算调整为三万元，优先上线移动端，交付时间仍待确认。”。

主代理验证 run 的 trigger_type 为 event、状态 succeeded；新 event 的 provenance 为 transcript，source_event_ids 指向刚上传的原始音频；收件箱中的转录与该 event 完全一致。第二次 tick 返回 idle，没有重复逻辑任务。这次小样本两次 tick 合计约 1.7 秒，不构成性能承诺。

此项证明真实事件发现、执行、提交及收件箱持久化；手机采集仍需真机验收。配置重跑与定时回顾证据见下节。

## 配置重跑与提交恢复

主代理通过真实 HTTP 修改转录提示词，再以固定 request_id 请求同一录音的第 2 代转录，实际 CLI 执行成功。新转录以 supersedes 指向旧转录，context 同时保留旧版本及其被取代状态。

- 相同 request_id 返回相同 run；同一输入仍有活动任务时，不同请求返回 409。
- 同一 attempt、fencing token 和候选重提返回原成功结果；篡改候选返回 409。
- 非法 attempt 路径返回 400；暂停安装后拒绝提交，即使重放之前成功的候选。
- 网页 390px 宽度实际完成配置编辑、非法 metadata 数组校验、修正后保存，以及暂停和恢复。四种语言均完成启停操作；填充真实回顾、长项目描述及事件 JSON 后，各语言 document 宽度和 scrollWidth 均为 390px。

### 语言状态

### OAuth 浏览器证据

新建隔离后端、测试账号、OAuth client 和临时 localhost HTTPS 代理。浏览器工具拒绝自签证书，因此真实交互改为同一后端已有的 `http://localhost:8450` 回环监听，没有改动产品 HTTPS 配置、CSRF、Secure cookie 或系统证书信任。

四种语言均检查了 OAuth 错误密码反馈、同一 request_id 在切换语言后保持、登录后的用户身份与 read/write 范围说明，以及 390px 授权确认页无溢出。最终授权 POST 返回 302，隔离数据库产生一条授权码记录。浏览器工具仍显示原授权页面，静态服务日志也未确认回调到达，因此不声称最终浏览器回跳或真实外部客户端接入已通过。

临时 OAuth 代理及后端在验收后停止；不保留其临时凭据、私钥和数据。只保存不含凭据的 `locale-oauth-proof.json`。

### 手机恢复缺陷与修复

- 原先崩溃后的 recording 队列项只改为 interrupted，没有补齐大小与哈希，显式重试必然失败。现在读取真实非空片段、重算大小和 SHA，并保持“中断片段”状态；不存在或空文件标记失败，不显示已恢复。
- 完成录音先清理活动标记和计时器、停止 recorder，再等待队列读取；取消只在实际保存成功时显示已保存。
- 权限和队列写入的 await 后复核账户与项目，仅移除无媒体文件的未启动占位。录音或启动期间禁止切换归属；退出与登录过期先保存已有片段，阻止期间新开录音。
- APIClient 按实际发送的同一份 Data 再核对大小与 SHA，避免文件在前一次校验后变化并被上传。远程播放响应也核对当前项目。
