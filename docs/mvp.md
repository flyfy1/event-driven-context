# Initial Release Scope

English | [简体中文](mvp.cn.md)

> This document preserves the existing storage and query baseline. For the complete product direction as of 2026-09-12, see [Product Design](product.md); for the implementation approach, see [Technical Design](technical-design.md). The scope of the next validation cycle is defined in Section 10 of the product design. The new design does not mean that the corresponding capabilities have already been implemented.

- Users: People who use the CLI or MCP to accumulate raw information for team projects.
- Task: Reliably append text or text files and retrieve them by time and metadata.
- Core hypothesis: Flexible metadata combined with time-based queries is sufficient for initial human and agent retrieval.
- End-to-end loop: Register and sign in → create a project → add a member → have two users append events → query, read files, and discover metadata.
- Evidence of success: Real CLI and official MCP clients invoke the service over HTTP and stdio; cross-project access is denied; data survives restarts; events and original files are stored in a Git-ignored data directory; SQLite does not store event content.
- Scope: A Go monolith, SQLite for identity and authorization, and file-backed event data; projects contain events directly; project creators manage members, while all members have equal read and write access; events cannot be modified or deleted; flexible JSON metadata.
- Input: Direct text or UTF-8 text files with an explicitly declared MIME type, up to 1 MiB each. Files use an extensible base64 byte envelope so that other MIME types can be supported in the future without changing the event structure.
- Time: `recorded_at` is generated by the server; `occurred_at` is optional. Queries use `recorded_at` by default, and time ranges are `[from,to)`.
- Metadata: Supports exact JSON equality and existence checks for top-level keys, with conditions combined using AND; lists fields, types, and event counts; and returns distinct values and counts for a single field. All operations are restricted by project permissions.
- Access: Local Codex and Claude Code invoke the HTTP API through the authenticated `edc` CLI rather than registering MCP; the CLI reads a static Bearer token privately. For the ChatGPT web custom connector, production Streamable HTTP additionally provides OAuth 2.1 Authorization Code + PKCE (S256), discovery, DCR, and the `context:read` / `context:write` scopes. The main web app and OAuth pages fully support English, Simplified Chinese, Bahasa Melayu, and हिन्दी, including registration and sign-in, the project and event workspace, dynamic states, validation, and errors. On first use, the browser's system language is selected; if it cannot be read or is unsupported, the app falls back to English. A manual language selection persists across refreshes, sign-in, and both subdomains. Newly registered users are not automatically added to existing projects. Every access path reuses the same users and project membership permissions.
- Out of scope: Editing or deleting events, asynchronous consumers, message queues, automatic summarization, and vector databases; OAuth does not yet provide refresh tokens, third-party identity providers, or an administrator client console.
- Delivery boundary: Deliver and validate the end-to-end loop above before discussing data-processing logic.
