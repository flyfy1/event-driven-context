## 方法级反例

`results/stress/deterministic.json` 保留互补事实误冲突、未来生效过早失效、同内容不同 ID 重复三个失败。前者说明 topic 相同且文本不同远远不够判断矛盾；后者分别要求有效时间语义和来源别名归并。`same-id-retry` 通过只证明 UUID 幂等，不证明语义去重。

冻结 State 的老预算即使带过期提示也被 reader 使用；尾部补读修复了这三个模板变体。原始三条件输入/输出在 `results/stress/answers.jsonl`。这表明“模型看见警告”与“系统禁止输出过期当前值”是两种不同能力。

更紧凑的 B 并未稳定保留长期事实：`results/compact-product/snapshots/product-0-53.json` 只剩最新预算，早期目标和硬约束丢失。早期摘要还将完整 UUID 缩短至八位，降低可定位性。部分 compact 回答使用 Xiao Ning 等音译，规则评分错误地判为不匹配；因此也不能只凭 10/21 对 13/21 认定语义质量退步。

## 公开长历史上的评分反例

LongMemEval-S 的 `5c40ec5b` 标准答案是 “We've met up twice.”；A/C/D 都回答 “Twice”，语义正确，但子串规则未通过。原文 e00470/e00478 明确说已见面两次。第二题 `0ddfec37_abs` 问签名橄榄球数量，记录只有签名棒球，四组均拒答。两个题不足以评估总体质量，也没有运行官方模型 judge。

公共主跑的代表性案例与引用复核在 `results/manual_audit.md` 中另列。事件 ID 存在、出现在 reader 上下文、命中 gold 以及原文确实支持答案是不同指标；显示括号可无损规范化，短 ID 和虚构 ID 不会自动补齐。

LoCoMo 同时暴露规则假阳性：Rome 原文为 6/19 的“上周去过”，D 回答 6/19，因包含 June 2023 通过，却擅自给了具体日期。另有原题问 5/23 的 internship，原文 5/27 只说刚被接收；这个日期前提未被证据支持，故将 reader 的谨慎回答标记为争议/部分正确，不强改 gold。

`locomo-0/q103` 是 D 的真实检索回退：C 在 1510 tokens 内取到童年书名的 e00102；D 在 1485 tokens 内加了较多前邻轮次与状态头，反而没装入 e00102。这说明关系/邻居扩展有机会成本，推荐实现应优先真正的更正和来源依赖，不能默认大量相邻聊天都值得注入。

MemoryAgentBench 上，“取到了最新事实”仍不够：`mab-0/4/q30` 的原始事实 382（Japan）和旧 160（USA）都在 C/D 背景内，二者仍回答 USA。`mab-0/0/q41` 更新后死亡地点为 USA、其语言为 German，两条最新事实也都在背景中，reader 却继续输出 conflict。这些是该虚构基准下的更新应用失败，不是真实世界知识判断。

`mab-0/0/q30` 的 D 答案 New York City 虽匹配 gold，但上下文缺少演奏者 Lou Reed 与 Fordham 的中间关系，引用还用了旧演奏者记录。复核标为“答案值正确，给定证据链不完整”，不能据此证明多跳检索成功。上述完整证据链在案例 JSON 的 `posthoc_manual_evidence` 中后补标注；这些标注从未进入构建或查询。
