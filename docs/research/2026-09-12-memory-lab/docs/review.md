# 方法审查与修正

只读研究子任务完成一轮独立方法审查，随后主协调者修正并验证。没有额外人类标注员参与；人工式逐条复核由本任务 agent 阅读原始答案和来源完成，不能声称独立人类盲评。

| 发现 | 处理 |
|---|---|
| 原 lag 场景只是重新更新后回答 | 在主结果中只算更新题；另有 stress 冻结旧 State、append 新预算、未告知/告知过期/尾部重放三条件，共 9 个 reader 探测 |
| B 未看到 D 的 topic/kind/ephemeral 元数据 | 暂停尚未回答的 main；所有方法渲染同样 metadata 和 source 后重跑；main/INVALIDATED.json 留档 |
| 引用 ID 出现在 refs 中就被算“有效” | 分成 ID 存在、选中原文可见、gold 来源精度/召回；原文蕴含另作人工式抽查。没有 gold 记 N/A |
| 自动 strict_answer 只是子串/status/禁用词规则 | 公开为“规则通过率”，不当完整正确率；抽查揭示否定句、正确释义、引用不完整与状态标签不一致 |
| 保存状态尚未计分 | analyze.py 对 33 个检查点输出活动条目保留、旧条目活跃、B 来源标记保留；B 标记是代理，另复核摘要正文 |
| MAB 最新规则可能被误读为检索显示次序 | 在进入公共样本前明确按原始事实编号决定最新值；保留 main-v1/SUPERSEDED.json，产品请求原样缓存复用 |
| 字段可靠性、隔离与重复的条件过强 | 明确源 metadata 是给定输入；相似项目测试只有硬范围，不测试自动路由；重复是同 UUID 幂等，不是语义去重；stress 显示不同 ID 重复失败 |
| summary prompt 的冗余可能造成人为劣势 | 另跑 compact 小样本敏感性，结果单独披露；不替换 main B |
| 构建/回答成本和缓存 | 按逻辑使用成本与实际去重请求分别输出；中断请求 token 未知，不当成 0；额外 API 支付为 0，不代表电力/时间免费 |
| 不应把准备 LME 文件写成已完整四组复现 | LME 两题只作 A/C/D/E 长历史探测；完整四组基准是 LoCoMo 与 MemoryAgentBench |

仍存在的限制：模板变体不独立；公共测试可能被预训练污染；事件 ID 级召回不代表选中 token span 蕴含；主题冲突规则过粗；未来生效尚未实现；没有真实音频识别、生产权限/崩溃恢复、客户端自然行为和人类长期使用验证。
