# Event-driven Context memory：研究与实验报告

执行日期：2026-09-12。范围：公开数据与新生成的合成项目；现有产品仓库只读。正式四组实验、补充探针与复核已完成。

## 建议采用什么

采用 **append-only Event + 带来源和更新关系的当前 State + 可重建检索索引**。先维护一份 `project-brief/current`，把目标、硬约束、当前关键决定、未完成工作和阻塞问题放入短概况；原始记录、过往版本、已完成事项和长论证按需检索。不要把反复改写的一篇摘要当作唯一事实库。

这个建议保留现有核心架构，不要求增加 Memory 实体、向量数据库或通用知识图谱。实验支持先把来源、显式更新、新鲜度和证据装包做正确；它尚未证明自动语义抽取、长期维护、多客户端使用或任意问题上的优势。完整结构、State key、更新规则和演变实例见 [结构建议](docs/structure.md)、[演变](examples/evolution.md) 与 [主开发接入建议](docs/implementation.md)。

## 实际运行了什么

先以 4 个问题、16 个回答冒烟，再扩大到 103 个问题、四组共 412 个回答。固定已有本地 `qwen3.5:35b-a3b-nvfp4`、Ollama 0.32.15、temperature=0、seed=912、think=false。权重 digest、调用参数、完整请求与原始响应均保留。没有购买 API 服务、下载新权重或扩大付费额度。

| 方法 | 构建与回答机制 |
|---|---|
| A 最近原始记录 | 原文按最近顺序装入背景；不做摘要 |
| B 持续项目摘要 | 每次只输入前一摘要和新事件，递归更新；摘要与回答背景同为 1536 token 上限 |
| C 有来源的原文检索 | 同一切块规则，BM25 检索原文及事件 ID |
| D 可追溯结构化证据 | 在原文证据上维护来源分类、状态和显式 refs；检索时补入更新、冲突同槽位与来源链；保留历史原文 |

四组使用相同 reader、问题与评分规则，证据含来源标签在内最多 **1536 cl100k_base tokens**。这是统一预算代理，另记录 Qwen 原生用量；系统指令和问题在预算外且各组一致。D 的全量证据集合是索引/存储，不是全量放进 reader。最早的几个项目检查点很短，A 可以容纳当时全部历史；长历史阶段与公共基准都严格限额。

构建器只得到事件和数字处理上界；不接触问题文本、答案、gold 来源或作者预制摘要。各问题使用当时冻结的快照，查询到来后才检索。LoCoMo 只输入原始轮次；MemoryAgentBench 只输入原始事实；LongMemEval-S 按会话日期排序，禁止使用未来会话。构建批次最多 4200 代理 tokens，B 最大生成 2048 原生 tokens，生成后再限制摘要体积。

**D 是可解释的抽取式原型，不是完成的语义理解系统。** 产品集给定正确 kind/topic/refs/ephemeral 元数据，所有组都看见相同输入。D 按这些信息做规则归并，公共数据没有这些产品标签。不同成员身份、项目范围和同 UUID 幂等也是给定或确定性约束，不能把相应分数解释为自动识别人、自动路由项目或语义去重的能力。

| 数据 | 本轮范围 | 选择理由与限制 |
|---|---|---|
| 产品专项 | 一个模板的 3 个参数变体；63 问、33 个 State 检查点 | 覆盖预算修改、待办完成/取消/重开、冲突、推断、重复、噪声、转录歧义/更正、同名项目、更新、未知等；变体不独立 |
| LoCoMo | 2 段完整对话，419/369 轮；约 15,252/11,530 原文 tokens；各 8 问 | 测长期对话、多跳与时间回忆；共 16 问，非全基准复现 |
| MemoryAgentBench | 456/2311 条事实，约 6,084/32,912 原文 tokens；24 问 | 单跳/多跳事实更新；按**原始事实编号**确定最新值，不按检索展示次序；与真实多人冲突语义不同 |
| LongMemEval-S 补充 | 2 条完整历史，约 102,808/103,132 原文 tokens；A/C/D/E 共 8 回答 | 检查十万 token 规模和拒答；为控制构建开销未跑 B，不能称完整四组复现 |

至少两个互补公共基准的四组流程实际跑通：LoCoMo 与 MemoryAgentBench。LongMemEval-S 是额外规模探针。选择规则、种子、原始问题索引、固定代码/数据 revision 与下载 SHA-256 见 [复现说明](README.md)、[样本清单](data/public_selection.json) 和 [来源](docs/sources.md)。

## 测得的结果

| 数据 | A 最近原文 | B 递归摘要 | C 原文检索 | D 结构化证据 |
|---|---:|---:|---:|---:|
|专项（每组63）|39/63（61.9%）|44/63（69.8%）|55/63（87.3%）|58/63（92.1%）|
|LoCoMo（每组16）|4/16（25.0%）|3/16（18.8%）|5/16（31.2%）|5/16（31.2%）|
|MemoryAgentBench（每组24）|1/24（4.2%）|3/24（12.5%）|8/24（33.3%）|10/24（41.7%）|

以上是**规则通过**，包含格式误判。专项 D 较好，公共题未显示足以宣称通用优越性的证据；尤其主 D 在没有显式 refs 的公开事实中，仍依赖 reader 理解更新。没有把各基准混成一个总分。

主表的“规则通过率”只是子串、状态、禁用词与部分精确引用检查的组合，**不等于官方分数，也不等于完整语义正确率**。原始字段不被复核覆盖。按题型、按历史、状态、引用、检索、体积及成本分别输出，见 [完整对照](results/summary.md) 与 `results/main-v2/aggregate.csv`。

### 比总分更重要的观察

- **新鲜度必须由流程保证。** 冻结旧 State 的 3 个模板变体都回答了旧预算；即使在 evidence 文本里附过期提示，3 个仍回答旧值。补取尾部事件后 3 个都回答新值。这支持把水位检查、尾部补读与不可更新时的保守返回放在 helper/host 控制逻辑里，而不是只写一句警告。
- **硬约束需要稳定可见。** 探索性动作探针给出一份看似可执行、但会把录音上传第三方的供应商流程。总背景同为 768 tokens，问题不含隐私关键词：query-only 3/3 批准；预留目标/约束 3/3 拒绝。此前较弱的提问两组都因缺少引擎而拒绝，不能证明 pinning 有效；这个后补探针是有意构造的单模板反例，不是普遍效果估计。
- **摘要的来源 ID 与事实可能脱节。** B 在 `product-0/historical` 保留最初预算事件的 ID，却把最初金额答成更正后的 30000（原值 50000）；在歧义转录问题上断言“林”，漏掉随后澄清时又无法回答。详情与原始上下文见 [失败案例](results/failures.md)。
- **缩短摘要提示词并未解决全部问题。** 单个产品历史的 compact B 规则通过 10/21，原 B 为 13/21。紧凑版早期把 UUID 缩成八位，后期有时只保存最新一条预算，旧目标和约束消失；个别英文音译又被规则误判。不能据此判定所有摘要方法都差，也不能用这组探索结果替换主 B。
- **摘要重复不是独立证据。** 两次插件摘要都追溯到同一次未确认推断的补充探针中，D 保留用户确认预算，reader 没把两篇摘要当两次用户确认。这里只测试给定来源链；未验证从自然语言自动识别伪造来源的能力。

### 保存正确与回答正确分开

33 个检查点共有 72 次必需活动条目检查，D 保留 72/72，已标注旧条目仍错误活跃 0 次；B 保留对应来源标记 68/72。后者不检查句子保真，已被“最初预算”案例证明不能单独作为质量指标。完整 State 体积与构建耗时在 `state_audit.json`；不把存储体积当成 reader 背景体积。

“保存状态”检查是对选定关键断言的审计，不是完整语义 gold；D 的模型构建用量为零，因为原型只是规则处理给定输入。建议中小 `current` State 是证据集合的投影；主 D reader 实际测的是证据缓存+状态+闭包，**没有直接验证完整生产插件发布和跨客户端注入路径**。示例的 10 个版本、81 个精确原文 span、最大 13 refs 通过离线检查，不能替代 API/权限验收。

原始 Event 保全与同 UUID 幂等是共享输入层的检查。A/C 没有整理后的活动条目集合，不强行套用 D 的 State 正确率；B 的来源标记指标也只是弱代理。这些口径不能当作同一种“保存准确率”直接排序。

### 公共基准、拒答和评分误差

空背景 E 的规则结果：locomo 4/16，unknown 16/16；mab 0/24，unknown 19/24。LoCoMo 本就含不可回答题，拒答能获得部分分数，因此 E 通过不自动等于泄漏。

复核发现三类重要偏差：日期顺序/正确释义造成假阴性；给出无依据的具体日期仍包含 gold 月份而假阳性；原文包含问题未证实的日期前提。另有 D 取入过多邻居而挤掉关键书名、最新事实已取到却仍答旧值，以及答案匹配但中间证据链缺失的真实问题。53 个定向复核输出含专项、公共题与长历史探针，不能将其有偏比例当总体准确率。

协调 agent 逐条阅读了选定回答、对应原文和摘要；[复核记录](results/manual_audit.md) 保留自动分数、正文判断和来源判断。这是定向人工式复核，**没有独立人类标注员，也不是盲评**。公开题可能被模型预训练见过，空背景 E 仅作诊断，不能证明消除了污染。

### 体积、成本与耗时

主实验 B 构建共 93 次逻辑调用，输入 385,249、输出 169,012 原生 tokens；其中 49 次返回 length，另有摘要体积裁剪。主实验 412 个 reader 回答共输入 752,438、输出 25,968 原生 tokens。各阶段实际成功请求去重后再加 16 次新发延迟校准，共 698 次，已知输入 1,385,181、输出 232,688 原生 tokens。详见 `build_costs.json`、`aggregate.csv` 与 `total_usage.json`。

独占延迟校准每组只有两个问题×两次，保留服务端前缀缓存；p50：A 1.14 秒、B 1.06 秒、C 1.03 秒、D 1.03 秒。这是量级校准，不能据此给生产吞吐承诺。

构建阶段有 36 次报告的原生输入加输出超过配置 num_ctx=8192；runner未独立观测后端的窗口滚动/截断语义。这是 B 的额外实现限制，不能将其结果外推为最强摘要系统的上限。reader 的证据预算、实际输入和响应仍逐条保存。

B 构建模型 tokens 与 reader tokens 分开计算；A/C/D 没有构建模型调用。原型 BM25 每次查询重新建立词项统计，检索耗时包含这部分 CPU 工作。主跑曾与补充实验在同一单并行模型服务上交错排队，因此主表请求 p50/p95 含排队，不能用于公平独占延迟排名；后续独占校准单列。中断中的请求无法回收 token 计数，记录为未知；电力和机会成本未测，不能把新增 API 支付为零写成“没有成本”。

D 的零模型构建用量来自处理给定元数据与 refs；从任意对话自动抽取这些信息的真实插件成本尚未测量。费用账本也不包含本会话协调与文献研究 agent 的 tokens。

## 仍然失败的地方

确定性扩展测试 7 项中通过 4 项，保留 3 个明确失败：同主题的互补事实被粗糙规则误判为冲突；未来生效的更正会过早废除旧值；相同内容不同 UUID 仍保留成两个条目。它们见 `results/stress/deterministic.json`，没有通过调规则后删除反例来美化结果。

此外，词法检索可能漏掉释义、隐含关联和长链条；关系闭包的当前 packer 不能保证整组证据原子装入预算；来源存在不保证原文支持生成结论。未知问题上 reader 可能正文说“不知道”却输出 `status=known`。这些问题需要分别解决，不能靠更长摘要或统一“confidence”分数掩盖。

本轮没有测试真实音频识别、可信用户确认身份、语义重复识别、实际跨项目自动路由、生产并发/恢复、多模型一致性或数月维护。`source.channel` 是来源声明，不是防伪的确认机制；agent 用用户令牌写入的 note 不能因此被视为用户亲自确认。

## 文献结论与本轮推断

检索覆盖截至执行日的主源，包括 2026-08 的 **StateMemBench**、09-03 的 **LoCoMo-Conv** 和 09-10 的 **Grounding Agent Memory**。近期工作更强调当前状态、依赖失效、隐含背景应用和环境验证；它们的作者成绩不是本轮测量。[StateMemBench](https://arxiv.org/abs/2608.19652v1)、[LoCoMo-Conv](https://arxiv.org/abs/2609.03467v1)、[Grounding Agent Memory](https://arxiv.org/abs/2609.11060v1)。

LoCoMo/LongMemEval 等属于基准，Mem0/A-Mem/Hindsight 等属于方法或系统，Codex/LangGraph 属于执行框架。候选能力、遗漏、成本、许可、可复现性和未运行原因逐项列在 [来源表](docs/sources.md)。未把较新的论文名称当作已经验证的最佳方案；LoCoMo 的非商业许可等权利限制也没有因本地下载而消失。

**从实测推导的设计**：保留原始证据，以显式更新关系控制当前视图；硬约束优先进入启动背景，详细事实随问题取；按水位增量更新并能从 Event 重建。**尚未验证的假设**：一份小 State 的具体最佳预算、何时拆分、语义抽取模型和混合检索是否值得其成本。先用现有架构做可验收的垂直切片，再对失败类型补实验。

## 最小交付与下一步

主开发优先实现来源条目校验、显式 refs 更新、水位/尾部门禁和从引用打开原文。当前已有版本化 State、expected_version、lag、同项目 refs 校验及插件命名空间，先扩展插件 data 和调用方 helper；只有实际触及来源容量、查询性能或可信认证需求时才改核心。

独立目录内含全部复现脚本、配置、产品专项数据、原始模型请求/回答、失败与重试说明、结构及演变例子。按 [README](README.md) 可复跑；[执行记录](results/execution.md) 说明有效运行、作废阶段、代码版本与耗时。实验期间产品仓库只读；按用户后续追加授权，全部材料另归档到产品仓库的 `docs/research/2026-09-12-memory-lab`，这是唯一新增写入范围。没有修改生产环境、用户客户端配置或其他任务文件，也没有读取或上传私人对话。
